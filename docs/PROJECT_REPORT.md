# דוח פרויקט קבוצתי: מערכת מארגן ערב משחקים
**חברי הצוות:** אלעזר ערנטרוי,מענדי זילבר, חבר צוות 3, חבר צוות 4  
**קורס:** סדנת תכנות בפייתון ובגיט | שנת 2026  

---

## 1. הגדרת הצורך וקהל היעד
מפגשי ערב משחקים מרובי משתתפים מתאפיינים פעמים רבות בהתלבטות ממושכת סביב בחירת המשחק המתאים. המשתתפים נדרשים להתחשב במספר השחקנים הנוכחי, במסגרת הזמן העומדת לרשותם ובהעדפות סגנוניות מגוונות (משחקי אסטרטגיה מורכבים מול משחקי מסיבות קלילים). מערכת "מארגן ערב משחקים" נועדה לתת מענה ממוקד, מהיר ושקוף לבעיה זו, באמצעות ניהול מאגר משחקים והפעלת אלגוריתם המלצה המדרג את האפשרויות האופטימליות ומספק נימוק ברור לכל בחירה.

קהל היעד כולל מארגני ערבי חברה, משפחות, חוגי משחקים וקהילות גיימינג המחפשים כלי יעיל להחלטה מהירה ומבוססת נתונים.

## 2. ייחוד המערכת והשוואה לפתרונות קיימים
בשוק קיימות פלטפורמות שונות לניהול והמלצת משחקים, ובראשן:
1. **BoardGameGeek (BGG):** מאגר המידע העולמי והמקיף ביותר למשחקי קופסה. מציע חיפוש מתקדם ודירוגי קהילה. חסרונו העיקרי הוא עומס ממשקי כבד, הצפת מידע וחוסר יכולת לבצע התאמה מהירה בזמן אמת לקבוצה ספציפית בתוך שניות.
2. **Board Game Arena / מנועי המלצות מקוונים:** מתמקדים במשחק אונליין או בהמלצות כלליות מבוססות אלגוריתם שאינו שקוף למשתמש.

**ייחוד המערכת שלנו:**
המערכת פועלת באופן עצמאי לחלוטין ללא תלות ברשת (Offline-first), ללא צורך בהרשמה או התקנת ספריות כבדות, ומציגה "אלגוריתם שקוף" המפרט בדיוק מדוע משחק מסוים קיבל ציון גבוה (שקלול תגיות וקרבה למגבלת הזמן), לצד מנגנון מובנה לשבירת שוויון.

## 3. ארכיטקטורה, טכנולוגיות והחלטות טכניות
המערכת פותחה בשפת Python 3 תוך הסתמכות בלעדית על הספרייה התקנית.
המבנה פוצל לארבעה מודולים בלתי-תלויים:
- `games_data.py`: ניהול הרשומות, ולידציה ובדיקת תקינות הקלט. הפונקציות טהורות ואינן מבצעות mutability על הנתונים המקוריים.
- `recommender.py`: ליבת הלוגיקה העסקית. ביצוע סינון קשיח (Hard filter) למניעת חריגות, ולאחר מכן ניקוד מדורג ושבירת שוויון רב-שלבית (משך משחק ולאחריו סדר אלפביתי).
- `search_reports.py`: שאילתות חיפוש תגיות ודוחות סטטיסטיים.
- `main.py`: ממשק משתמש טקסטואלי (CLI) המטפל בקלט, שגיאות והצגה.

**החלטה טכנית מרכזית:** הפרדה מוחלטת בין שכבת הקלט/פלט (`input`/`print`) לבין שכבת הלוגיקה העסקית. החלטה זו אפשרה כיסוי בדיקות יחידה של 100% ללוגיקת ההמלצות ללא צורך ב-mocking מורכב לקלט משתמש.

## 4. מקורות ושימוש בעזרה חיצונית
- תיעוד רשמי של שפת Python בנושא מבני נתונים ומודול `unittest`.
- מאגר החוקים והקטגוריות מתוך BoardGameGeek (BGG) להגדרת תגיות המשחקים ההתחלתיים.
- נעשה שימוש מושכל במודלי בינה מלאכותית לגיבוש תרחישי בדיקות יחידה ומקרי קצה (Boundary testing), כאשר כל קוד נבדק ואומת עצמאית על ידי חברי הצוות.

## 5. חלוקת תפקידים ותרומת חברי הצוות
- **אלעזר ערנטרוי:** ארכיטקטורת המערכת, ממשק משתמש `main.py`, שילוב רכיבים (Integration) וסקירת קוד.
- **מענדי זילבר:** מודול נתונים ואימות `games_data.py`, כתיבת בדיקות אימות ואי-השתנות.
- **חבר צוות 3:** מודול הלוגיקה המרכזית `recommender.py`, אלגוריתם שבירת השוויון ובדיקות קצה.
- **חבר צוות 4:** מודול חיפוש ודוחות `search_reports.py`, כתיבת דוח הפרויקט והבדיקה ההדדית.

## 6. מערך הבדיקות ומגבלות
נכתבו 6 בדיקות אוטומטיות ב-`unittest` המכסות:
1. תרחיש רגיל ומדויק של דירוג המלצות.
2. טיפול במאגר ריק.
3. דחיית קלט שגוי (מקסימום שחקנים נמוך ממינימום).
4. מקרה גבול מדויק על סף הזמן והמשתתפים.
5. לוגיקת שבירת שוויון מורכבת.
6. עקרון ה-Immutability של רשימת הנתונים בעת הוספה.

**מגבלות ידועות:** המערכת פועלת בזיכרון המקומי בלבד (Volatile memory). בהרחבה עתידית ניתן להוסיף שמירה לקובץ JSON/SQLite וממשק גרפי מבוסס Web.
